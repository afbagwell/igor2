# BUG-016 — An empty `networkPassword` mangles every Arista error message

**Status:** open · **Component:** core · **Severity:** medium
**Found:** 2026-07-31 · **Version:** v2.3.2

Index: [bug_tracker.md](bug_tracker.md)

---

## Location

`internal/app/igor-server/network_arista.go:83-90`, in `aristaJSONRPC`:

```go
resp, err := client.Do(req)
if err != nil {
    // replace the password with a placeholder so that it doesn't show up
    // in error logs
    msg := strings.Replace(err.Error(), password, "<PASSWORD>", -1)
    return nil, fmt.Errorf("post failed: %v", msg)
}
```

## Cause

`strings.Replace` with an empty `old` argument does not no-op. It matches the empty string
at every position, inserting the replacement between every rune of the input — the
documented behaviour, and the reason the standard library counts `utf8.RuneCountInString(s)+1`
matches for an empty pattern.

`igor.Vlan.NetworkPassword` is legitimately empty on many deployments. The shipped
configuration documents it as optional (`cmd/igor-server/igor-server.yaml:344-346`):

```
# networkPassword (string) - The service password for the user specified above. Leave blank if no password is needed.
# Default: (blank)
```

So on any site whose switch account needs no password — which includes the Sandia
production instance, where `networkUser` is the service account `igor` with no password —
`password` is `""` and every error message from this path is destroyed.

## Reproduction

Demonstrated directly against a representative transport error:

```

  <PASSWORD>p<PASSWORD>:<PASSWORD>/<PASSWORD>/<PASSWORD>s<PASSWORD>w<PASSWORD>/<PASSWORD>c
  <PASSWORD>o<PASSWORD>m<PASSWORD>m<PASSWORD>a<PASSWORD>n<PASSWORD>d<PASSWORD>-<PASSWORD>a
  <PASSWORD>p<PASSWORD>i<PASSWORD>"<PASSWORD>:<PASSWORD> <PASSWORD>d<PASSWORD>i<PASSWORD>a
  <PASSWORD>l<PASSWORD> <PASSWORD>t<PASSWORD>c<PASSWORD>p<PASSWORD>:<PASSWORD> <PASSWORD>i
  <PASSWORD>/<PASSWORD>o<PASSWORD> <PASSWORD>t<PASSWORD>i<PASSWORD>m<PASSWORD>e<PASSWORD>o
  <PASSWORD>u<PASSWORD>t<PASSWORD>
```

Two preconditions, both ordinary: `vlan.network` set to `arista`, and `vlan.networkPassword`
left blank as the shipped configuration explicitly permits. The error itself needs only a
switch that is unreachable, slow, or refusing the connection.

**Not reproduced end to end against a live switch**, because the production instance has
had no Arista transport errors to mangle — see Impact.

## Impact

Diagnostic only; nothing malfunctions and no secret is exposed. But the timing is
unfortunate, because this is the exact message an operator needs while investigating
[BUG-008](BUG-008.md).

The corruption is confined to the inner `err.Error()` text. The wrapper added by the caller
survives intact — `installReservations` produces
`error setting network isolation: post failed: <mangled>` (`scheduling.go:546-548`). That
matters for two reasons:

- Searching the log by the wrapper text still works. The production check that returned
  zero hits for `error setting network isolation` across two days of logs is therefore
  valid, and its conclusion — that VLAN operations are succeeding — stands.
- An operator searching for the *inner* text, such as a hostname, a port number, `timeout`,
  or `connection refused`, will find nothing. Every one of those strings has `<PASSWORD>`
  interpolated through it.

So a site running with a blank password gets log lines that are unsearchable and unreadable
for the one failure mode hardest to diagnose from the outside. Given that the surrounding
investigation turns on distinguishing a stalled connection from a refused one, losing the
transport error text is a genuine cost.

Worth noting the scrubbing itself is sound in intent and works correctly when a password is
set. The defect is only the missing guard for the empty case.

## Suggested resolution

Guard the replacement:

```go
msg := err.Error()
if password != "" {
    msg = strings.ReplaceAll(msg, password, "<PASSWORD>")
}
return nil, fmt.Errorf("post failed: %v", msg)
```

Better still, remove the need for scrubbing. The credential only appears in the error text
because it is embedded in the request URL (`network_arista.go:77`):

```go
path := fmt.Sprintf("http://%s:%s@%s", user, password, URL)
```

Using `req.SetBasicAuth(user, password)` against a credential-free URL keeps the secret out
of `err.Error()` entirely, at which point the `strings.Replace` can be deleted rather than
fixed. That is the change worth making, and it also removes the risk of the credential
reaching any other formatter that handles the URL.

A regression test can assert that an error message is returned unchanged when the password
is empty, which fails against the current code.
